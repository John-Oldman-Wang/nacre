# 页面的出现和消失：四个事件是怎么来的

`beforeappear`、`appear`、`beforedisappear`、`disappear`。用法见 [API 文档](../api/ui-view-controller.md#页面的出现和消失)。

文件：`ios/Runtime/Bridge/NacreAppearance.mm`、`packages/types/ios/appearance.d.ts`、`acceptance/src/steps/appearance.js`。没有 JS 的 part：事件带的字段走通用的落点，不用写代码。

## 为什么是事件，不是继承

UIKit 里这四个时机没有通知，也没有委托，只有覆写点（`viewWillAppear:` 一组）。进度表里它们原来记在 M2「用 JS 继承原生类」下面，理由是「全是覆写点」。

2026-11-16 讨论 M2 时把这件事重新看了一遍，结论是不做继承，原生类继续 final：

- 压在 M2 后面的需求拆开看，最要紧的是这四个时机，而它们是**通知**：没有返回值，不改变系统的行为。按 API 设计原则第 5 条，重复发生的通知用事件。
- 做成事件之后，继承带来的两个问题都不存在：不用解决「JS 子类的包装被回收重建之后字段丢失」，也没有「覆写时忘了调 `super`」。
- 其余的覆写点收益窄，或者有别的路：`drawRect:` 能画的东西图层基本都能画；视图想要的大小靠约束；直接收触摸有手势识别器。

讨论里一并否掉的是布局变化的事件（`layoutSubviews`）。布局绝大多数是 JS 自己引起的，做完调一次 `layoutIfNeeded()` 就读得到结果；系统自己引起的重新布局里，文字大小有 `traitchange`，键盘有 `keyboardLayoutGuide`，剩下的（旋转、半屏卡片被拖动）现在都还没有。会受影响的只有手动按 `frame` 摆的子图层。等真有人被挡住再做。

`viewDidLoad` 没有给事件。页面和它的视图都是 JS 建的，不需要系统告诉它「建好了」。

## 怎么接的：替换基类上的四个方法

两种接法：

| | 做法 | 结果 |
| --- | --- | --- |
| 运行时自己编译几个页面子类 | `new UIViewController()` 实际建的是运行时的子类，它覆写这四个方法 | 每种页面要一个子类（普通页面、导航、标签栏），要改核心里造页面的几处；宿主自己的页面、系统给的页面没有这些事件 |
| **替换基类上的方法**（用的这种） | 把 `UIViewController` 自己的 `viewWillAppear:` 等四个方法换成运行时的版本：先调原来的实现，再派发事件 | 一个新文件，核心不用改；对每一种页面都有效 |

替换基类够用，是因为子类覆写这四个方法时 Apple 要求调 `super`，所以基类的实现一定会被调到。四个方法都是 `UIViewController` 自己实现的，不是从父类继承的，直接交换两个实现就行。

替换会影响进程里所有的页面，包括宿主自己的和系统的。为了把影响压到最小：

- **替换是惰性的。** 第一次有人监听这四个事件之一时才换。App 不用这四个事件，进程里的页面和没有这个文件时完全一样。
- **换了之后，没人监听的页面只多一次关联对象的查询**，不过桥，不进 JS。
- 换上去的版本先调原来的实现，行为不变。

别的 SDK 也常替换这几个方法（统计页面访问的那一类）。交换实现是可以叠加的，谁先谁后都能调到对方。

## 派发

和别的原生通知一样延后一轮，不能取消。事件带一个字段 `animated`：它是方法的参数，过后读不回来。

延后一轮意味着 `beforeappear` 的回调执行时，系统的 `viewWillAppear:` 已经返回了。它仍然早于转场动画结束，用来刷新内容是来得及的。

## 类型

四个事件名和事件对象（`UIViewControllerAppearanceEvent`）声明了，但页面的 `addEventListener` **没有为它们加重载**，回调收到的类型是普通的 `Event`，读 `animated` 要自己标一次类型。

试过用声明合并给 `UIViewController` 加一条重载。加上之后 `UIAlertController` 和 `UIActivityViewController` 不再和基类兼容：它们各自重新声明过 `addEventListener`，只收自己的那几个名字，而运行时它们确实不收这四个事件。要么给它们也加上这条重载（类型就撒谎了），要么不加。选了不加。事件名本身不受影响，页面的事件名在类型上本来就收任意字符串。

## 量到的

模拟器，iPhone Air，iOS 27.2。页面都是不带动画地呈现或推入的。

| 操作 | 派发的顺序 |
| --- | --- |
| 模态呈现一页 | 将出现 → 已出现 |
| 关掉它 | 将消失 → 已消失 |
| 呈现一个导航控制器 | 导航将出现 → 栈顶页将出现 → 导航已出现 → 栈顶页已出现 |
| 推入一页 | 旧页将消失 → 新页将出现 → 旧页已消失 → 新页已出现 |
| 返回 | 被弹出的页将消失 → 上一页将出现 → 被弹出的页已消失 → 上一页已出现 |
| 切换标签 | 新页将出现 → 旧页将消失 → 旧页已消失 → 新页已出现 |
| 被全屏的模态页盖住 | 下面的页：将消失 → 已消失；关掉后：将出现 → 已出现 |
| 被卡片样式的模态页盖住、再关掉 | 下面的页什么都不派发 |
| 子页面的视图加进屏幕上的父页面 | 子页面：将出现 → 已出现 |
| 父页面被关掉 | 子页面跟着：将消失 → 已消失 |

另外验到的：

- 在 `appear` 的回调里调 `becomeFirstResponder()` 返回 `true`。这是自动聚焦不再需要定时器重试的依据。
- 摘掉监听器之后不再派发。
- 没上过屏的页面，监听了也不派发。

推入和切换标签时两个页面之间的先后不一样，所以文档里写的是不要依赖它。

## 一条旧断言因此过时了

导航那一步原来有一条「不认识的事件名被拒」，例子用的正是 `'appear'`。它现在是合法的事件，那条断言换成了 `'viewappeared'`。只跑新步骤的快速验证看不到这条失败，是完整验收里出来的。

## 没验证的

- 用户左滑返回到一半又放手、用户把卡片拖走：只有真实触摸能触发。
- 窗口的根页面第一次显示时派不派发。验收里根页面在这一步之前就上屏了。
- 报错里列的事件名不全：页面上监听一个哪边都不认识的名字时，报错来自核心的页面分支，它列的是自己那张表，没有这四个。和多行输入、列表是同一个已知问题。
- 真机。
