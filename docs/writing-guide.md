# 文档写法

这份规范管 `docs/api/` 下的文档怎么写。`docs/internals/` 是设计记录，不受它约束。

样板是 [`api/ui-button.md`](api/ui-button.md)。拿不准时照它写。

## 读者是谁

做过前端或图形开发、有扎实的通用开发概念，但**没碰过 iOS** 的人。

| 不用解释 | 必须解释 |
| --- | --- |
| 视图树、事件监听、回调、Promise、坐标变换、帧 | 安全区、Auto Layout 约束、layout guide、点（pt）、控件状态、SF Symbols 等一切 iOS 特有的东西 |

iOS 特有的词第一次出现时，用一句话说清它是什么。能用 Web 的概念对照就对照，并且说出差别（「相当于 `<button>`，有两点不同」）。

## 读者要的两件事

读者打开一页文档，要的是**怎么用**和**什么效果**。整页的顺序按这个排：先让他把东西做出来，再让他查细节。

## 页面骨架

顺序固定。不适用的章节省略，其余不能调换顺序。

| 顺序 | 章节 | 写什么 |
| --- | --- | --- |
| 1 | 开头 | 一两句话说它是什么。对照 Web 里的对应物，列出差别 |
| 2 | 完整例子 | 从空白 App 开始、能直接运行的代码，分步加注释。后面紧跟**效果** |
| 3 | 常见用法 | 按「想做的事」分小节，每节是代码加**效果** |
| 4 | 概念 | 用这个类必须理解的几个概念，一个概念一节。没有就省略 |
| 5 | 成员说明 | 全部成员的速查。方法带例子、返回值、出错情况 |
| 6 | 与 iOS 原生写法的对照 | ObjC 和 JS 的对照表 |
| 7 | 还不能做的 | 按「想做的事」列，注明对应的原生能力 |
| 8 | 参见 | 相关页面，每条说明为什么相关 |

每页开头有 frontmatter：

```yaml
---
type: reference
native: UIButton      # 对应的原生符号，没有就不写
status: partial       # done | partial | planned
---
```

## 规则

### 例子

1. **每段代码后面都有「效果」。** 写屏幕上看到什么、用户操作时发生什么、控制台输出什么。一条一行。
2. **完整例子从空白 App 开始。** 包括建窗口和页面的那几行，复制进 `main.js` 就能跑。
3. **常见用法的例子可以省略建窗口**，但要在章节开头说明沿用了哪些变量。不出现没交代过的变量。
4. **小节标题是读者想做的事**：「禁用按钮」「加图标」，不是属性名。
5. **例子里用到的每个 API，本页或链接页里必须有说明。**

### 成员说明

6. **每个属性写明：类型、可读、可写、默认值、含义。** 可读和可写各占一列，写「是」或「否」，不合并成「读写」。
7. **数值必须写单位。** 长度写「pt」并链到[单位](api/units.md)。没有单位的写明它是什么：比例、个数、优先级。
8. **枚举的每个取值都写效果**，不只列名字。
9. **布尔属性两种取值的效果都写。**
10. **会变的值写清怎么得知它变了**：派发哪个事件。没有通知的写原因。
11. **方法写明：参数、返回值、出错情况。** 报错信息照运行时抛出的原文抄。
12. **同一组写法相同的成员合并成一张表**，共同的部分在表前说一次。不为了格式统一把每个成员都拆成一节。

### 语言

13. **用直白的技术词。** 不用「钉」「塌」「吃掉」「兜底」这类口语和比喻。
14. **一个概念只用一个词**，全站统一。
15. **一句话只说一件事。** 主语明确，短句。
16. **只写现在。** 不讲「原来怎样、后来改了」，那些进 `internals/`。
17. **正文中文。** 标识符、取值、报错信息保持英文原文。

### 事实

18. **类型和可读可写以 `types/` 为准。** 文档和类型定义不一致时，先查清哪边对。
19. **没在模拟器验证过的效果，标「未验证」。** 默认不标的都是验证过的，或直接来自代码。
20. **不知道的不写。** 不凭印象填数字。

### 提示块

21. 只用一种提示块，写成 `> **注意**：…`。用于不看就会出错的地方。一页里不超过五六处，多了就没人看。

## 写完自查

- [ ] 把完整例子复制出来，能不能直接运行
- [ ] 每段代码后面有没有「效果」
- [ ] 有没有没解释过的 iOS 术语
- [ ] 每个数值有没有单位
- [ ] 每个属性的可读、可写是否和 `types/` 一致
- [ ] 未验证的效果有没有标出来
- [ ] `bash docs/check-links.sh` 通过

## 其他类型的页面

| 目录 | 写什么 | 规范 |
| --- | --- | --- |
| `docs/api/` | 一个类或一组能力一页 | 本文 |
| `docs/guides/` | 跨多个类才能完成的任务 | 按步骤写，每一步有代码和效果。只涉及一个类的用法写进那个类的「常见用法」，不单独开指南 |
| `docs/internals/` | 实现原理、取舍、实测数据、被否掉的方案 | 叙述体，不受本文约束 |
